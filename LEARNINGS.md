### 2. Google Drive file upload technique (reusable, verified 3+ times)
Native file-picker dialogs opened by clicking "File upload" are invisible to Claude in Chrome (CDP only sees page/tab content, not OS-level windows). Reliable workaround, confirmed to work repeatedly:
1. Click "+ New" → "File upload" (this fires a native OS dialog).
2. Immediately press `Escape` (does not close the underlying hidden `<input type="file">`, just dismisses whatever page-level focus artifact appears).
3. Use `find` with a query like `"file input for upload"` — the hidden `<input type="file">` becomes queryable only *after* the "File upload" click has fired.
4. Call `file_upload` with that element's `ref` and the local file path — this injects the file directly into the input, bypassing the native dialog entirely.
5. Verify via the "N upload complete" toast, not just visual absence of errors.

The leftover native OS dialog (if any) is a harmless artifact — it does NOT block or interfere with the injection technique. It just sits there until the user manually closes it. There is no way for me to close it (no OS-level window control available; confirmed via ToolSearch and mcp-registry search — no remote-desktop/computer-use connector exists in this session). **Re-confirmed 2026-09-12 via a second method**: tried closing it with PowerShell (`Get-Process | Where MainWindowTitle`, then a full `EnumWindows` sweep for any visible window titled "Open") — found zero matching windows either way. This means the PowerShell/Bash tool runs in a session or sandbox isolated from the user's actual visible desktop, so it cannot see or control windows the user can see on their own screen. **DO NOT REPEAT**: don't re-attempt closing these dialogs via PowerShell/Bash window-enumeration tricks — it's been tried and confirmed impossible from this session. Just tell the user plainly to press Escape/Cancel themselves.

**Mitigation going forward**: since each "+New → File upload" click leaves one of these dialogs behind, and the user got annoyed after several stacked up during a multi-voice-test session (2026-09-12, testing Brian/Liam/George/Eric TTS voices with repeated Drive uploads), minimize the *number* of separate upload flows in a short span where reasonable — e.g., batch saving multiple generated files in fewer upload trips if the workflow allows it, rather than one upload trip per single test file.

### 3. Distinguishing generic keywords from proper nouns/brand terms
When building SEO keyword lists from vidIQ's "related keywords" output, results can include channel names, presenter names, or brand terms mixed in with genuine topical keywords (e.g., "jackson galaxy" — a real YouTuber/cat behaviorist — got surfaced as if it were a topical search term). **Rule going forward**: before finalizing a primary keyword, sanity-check it's not actually a proper noun (person/channel/brand). If a related keyword is *only* sourced from a proper-noun primary, or is itself a proper noun, scrub it.

### 4. "Breakout score" is channel-relative, not a global popularity measure
vidIQ's breakout score measures how much a video over-performs *relative to that specific channel's own average* — not absolute popularity. Example: a video with 1,279 breakout score from a low-baseline channel can represent a much bigger "unicorn" moment than a 2.65M-view video with breakout score 4.9 from an already-large channel. When ranking/prioritizing videos to emulate, breakout score tells you "how surprising was this for the channel," not "how big was this in absolute terms" — both matter but answer different questions.

### 5. YouTube relevance-filtering methodology (established this session)
For checking whether a keyword is "on-topic" for a niche: run `vidiq_youtube_search` (type=["video"], limit=10) for the exact keyword string, then inspect titles/channels/descriptions of the top 10 results. Keep the keyword if **at least one** of the top 10 is genuinely about the target topic (here: cats, or cats+humans). This is a low bar by design (per explicit user instruction) — a keyword doesn't need to be *dominated* by on-topic content, just needs *some* presence. Applied to 72 keywords; only 3 failed outright (zero on-topic videos in top 10): "pet facts" (all other pets, no cats), "loss of appetite" (human medical), "clicker training" (all dog training). Ambiguous/ironic naming (e.g., "cat fan lovers" returning literal cat-vs-ceiling-fan videos, "cat lovers society" returning an unrelated music band by that name) still PASSED because genuine cat content was mixed in among the results — the keyword itself still routes searchers toward cat content some of the time.

### 6. Reusable content technique discovered and documented
"Vòng Lặp Có Kiểm Soát" (Controlled Open Loop): a video succeeded (2.65M views) *despite* its title asking a question the body never answered, because of layered effects — universal-mystery hook, high payoff density elsewhere in the video, a repeated "you thought X, actually Y" framing, and critically: giving viewers a *framework* to project their own emotionally loaded memories onto (this drove by far the highest-engagement comments). The unresolved title question itself became a lightning rod for debate/engagement. Verified via engagement-rate comparison that this was accidental (an AI-script-generation artifact — title optimized separately from body) rather than a deliberate technique, but the *mechanism* is reusable and worth deliberately replicating (see the wiki page's 6-step application framework). ### 7. Drive can prompt "file already exists" even right after "Move to trash"
When re-uploading a corrected file with the same name immediately after trashing the old copy, Google Drive can still surface an "Upload options — [filename] already exists in this location" dialog (choices: "Replace existing file" / "Keep both files"), rather than uploading cleanly. Likely cause: trash-processing lag, or the trashed item isn't fully purged from the folder's namespace instantly. **Safe handling**: "Replace existing file" is pre-selected by default and is the correct choice — click it, then "Upload". Verify completion the same way as a clean upload (the "N upload complete" toast + updated file metadata, e.g. new "Version N" label and modified timestamp). Don't treat this dialog as an error requiring a different workflow — it's a normal variant of the same upload path.

## Edge cases and patterns discovered
- Keywords that are literally ambiguous in English (e.g., "cat fan lovers" — could mean "fans of cats" or "cats + electric fans") can still pass a topical relevance filter if the accidental/literal interpretation still surfaces genuine on-topic content.
- A branded/proper-noun collision can exist even for a generic-sounding keyword ("Cat Lovers Society" is both a plausible topical phrase AND the name of an actual (unrelated) music act) — worth a quick gut-check when a keyword's top results skew unexpectedly toward one unrelated source.
- Vietnamese filenames with diacritics (e.g., "Từ khoá.xlsx") work fine end-to-end through Bash `mv`, Python `open()`, and the Drive file_upload tool — no encoding workarounds were needed in this environment.
